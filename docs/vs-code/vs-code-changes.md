# What Ember changes in VS Code

Every change Ember.app makes to the editor it is built on: what you see, why, and what stock VS Code or VSCodium does instead.

Ember.app is VSCodium with Ember's extensions built in and a few changes the extension API can't make. This list is generated from the build itself, so it is complete for this version. Everything else is the editor you know.

| Change | In Ember.app | Why | In stock VS Code or VSCodium |
|---|---|---|---|
| **Ember's name, icons and data folders** | The app is called Ember, with its own icon, URL scheme and user data folder, so it runs next to VS Code or VSCodium without sharing settings or extensions. It never updates itself back into VSCodium. | Ember is its own app; mixing profiles with another editor would break both. | VSCodium's name, folders and update server. |
| **Proposed APIs for Ember's extensions** | Ember's extensions use a few editor APIs that aren't final yet: inline removed lines, Keep / Undo on editor and diff toolbars, terminal selection, the built-in browser and Tab's inline predictions. | These features can't be built with the stable extension API alone. | Extensions can't use proposed APIs; Ember falls back to simpler behaviour. |
| **Ember's extensions and defaults built in** | Ember, Ember Tab and the Ember Light / Dark themes come built in, with Ember's layout and editor defaults (chat on the right, JetBrains Mono, the Ember theme and Ember's stroke icons). | Ember works out of the box, with no extension installs. | You install Ember's extensions yourself and keep VS Code's defaults. |
| **Drop files into the chat without Shift** | Dragging a file, tab or selection over Ember's chat drops it into the chat directly. | The editor blocks drops into webviews unless you hold Shift; the chat is meant to take them. | Drops into a webview need Shift held. |
| **Drags into the chat finish cleanly** | After a drop into the chat, the editor's drop overlays go away at once. | A drop the editor didn't see would otherwise leave its drag state behind. | Not needed: webviews don't take drops without Shift. |
| **Repository, worktree and branch in the window title** | The window title can show the repository, the worktree and the branch Ember's chats work in. | With one window per checkout, the title tells windows apart. | The title shows the folder name and VS Code's own variables only. |
| **A wider chat side bar** | The chat's side bar starts wide enough for the chat and Work on large windows, and narrower on small ones. | The secondary side bar's default width is too narrow for a chat. | The secondary side bar starts at about 300 pixels. |
| **Workspace trust off by default** | A folder opens with Ember's chat and Tab working; you can turn workspace trust back on in the editor's settings. | In Restricted Mode the editor disables Ember's extensions, which leaves the chat empty. | New folders open in Restricted Mode until you trust them. |
| **No prompt for a folder's automatic tasks** | A folder's tasks that run when it opens never run unless you turned automatic tasks on yourself (Tasks: Manage Automatic Tasks); the editor no longer offers to allow them. | With workspace trust off, that one-time offer is all that stands between a cloned repository's tasks and your machine. | The editor asks once; allowing turns automatic tasks on for every folder. |
| **No Welcome page when an extension installs** | Installing an extension doesn't open its walkthrough. | Ember's own Welcome launchpad replaces the editor's getting-started pages. | An extension's walkthrough opens VS Code's Welcome page when it installs. |
| **Ember's start page instead of VS Code's Welcome** | VS Code's Welcome page never opens at startup; Ember's Dashboard can, or its Welcome in a window with no folder (Settings › General). | One start page, about your work in Ember. | VS Code's Welcome page opens at startup. |
| **Light or dark with your system** | Window chrome follows your system's light or dark appearance. | Ember Light and Ember Dark switch with the system. | Window chrome follows the color theme, not the system. |
| **About opens Ember's About tab** | About (in the app menu on macOS, in Help elsewhere) opens Ember's About tab with versions and diagnostics. | Ember's version, account and diagnostics in one place. | A small dialog with the editor's version. |
| **Ember Settings in the Preferences and gear menus** | The Preferences and gear menus have Ember Settings…, above the editor's own settings (now called Editor Settings). | Ember's settings are one menu away. | Only the editor's Settings. |
| **A short Ember Help menu** | Help has Ember Help, Search Ember Help…, Keyboard Shortcuts, What's New in Ember, Welcome (Ember's launchpad), Get Started with Accessibility Features, Check for Updates… and a Troubleshooting submenu (Show Ember Log, Copy Diagnostics, Toggle Developer Tools, Open Process Explorer). Nothing in it links to Microsoft's or VSCodium's websites. | Help about Ember, and nothing that sends you to another product's pages or issue tracker. | VS Code's walkthroughs, documentation, videos, tips, feature requests, Report Issue and licence links. |
| **Only Ember's getting-started pages** | VS Code's own walkthroughs (Get Started with VS Code, Learn the Fundamentals) don't show; the accessibility walkthrough stays. Ember's Welcome has a Learn Ember card that opens Ember Help. | Their videos and links are about VS Code and point to Microsoft's site. | VS Code's walkthroughs on the Welcome page and in Help › Open Walkthrough…. |
| **A browser-height title bar** | The title bar is 40 px tall, like a browser's, so the workspace tabs have room; the macOS window buttons stay centred in it. | Workspace tabs need a taller title bar than an editor's title. | A 28–32 px title bar. |
| **Workspace tabs in the title bar** | Each window's title bar shows its workspace tabs, with + and ⌄ buttons, hover cards and drag to reorder, tear off or merge. | An extension can't draw in the title bar. | One workspace per window; the title bar shows only the title. |
| **Editor tabs that match the workspace tabs** | Editor tabs have rounded tops resting on the editor, the open one with a clay edge along its top, a soft hover and round close buttons, like the workspace tabs above them. | The two rows of tabs look like one design. | Square editor tabs with borders and a straight top accent line. |
| **JetBrains Mono built in** | The editor and the terminal use JetBrains Mono by default, bundled with the app. | One code font on every platform, loaded before the editor measures it. | The platform's monospace font. |
| **Larger new windows** | New windows open at 1680 × 1050 (fitted to your screen and centred), so the editor keeps room between Explorer and the chat. | The chat side bar needs room next to the editor. | New windows open at 1200 × 800, or 1440 × 900 with a folder. |
| **Window screenshots for your phone** | With Settings › Remote's screenshots on, your phone can show Ember's windows. The debugging port is on 127.0.0.1 only and exists only while that setting is on. | An extension can't capture the window. | No window screenshots. |
| **A dock badge for what needs you** | The app icon shows how many things need you, across every window: the number the title-bar pill and the Dashboard show. | An extension can't set the app icon's count. | No such badge. |
| **Notifications in Ember's name** (macOS only) | macOS notifications say Ember, with its icon and buttons (such as Accept and Reject), and open the chat when you click them. | Notifications an extension sends otherwise come from a helper app. | No such notifications. |
| **Ask before quitting while chats work** | Quitting while chats are still working asks first, and can resume them next time. | An extension can't stop a quit. | Quits right away. |
| **The native About panel says Ember** | macOS's About panel shows Ember's version, the editor version it's built on, and credits. | The app is Ember. | VSCodium's version and credits. |
| **Windows grouped as tabs** | Repositories and worktrees open as tabs of one window (on by default, `ember.tabs.enabled`): switching shows the tab's workspace in place, and tabs can sleep, come back after a restart and open from the Explorer. | An extension can't group windows. | Every workspace is its own window. |
| **VS Code's UI text says Ember** | Messages that name the app ("Restart VS Code…") name Ember. | The app you run is Ember. | Messages name VS Code or VSCodium. |
| **Built-in extensions say Ember** | The few built-in extensions that name the editor in their settings and commands name Ember. | Consistent naming. | They name VS Code. |
| **The microphone prompt says Ember** (macOS only) | The first time you talk back to a chat, macOS asks whether Ember may use the microphone, in Ember's words: it listens only while you talk back. | macOS asks on behalf of the app; the text is the app's own. | VSCodium's prompt names Visual Studio Code. |
| **Ember may recognise speech** (macOS only) | When you talk back to a chat, your words can be recognised on this Mac. macOS asks first, in Ember's words. | macOS needs the app's reason before it allows speech recognition. | VSCodium gives no reason, so it can't use speech recognition. |
| **The Ember mark as the product icon** | The editor's own product icon (Welcome, banners) is the Ember mark. | Consistent branding. | VSCodium's icon. |
| **What needs you, in the title bar** | A pill next to the command center says how many things need you and how many chats are working, in every Ember window; click it for Needs You. Source builds only. | The extension API can't put anything in the title bar; Ember's own workbench code can. | Nothing in the title bar about agents or what waits on you. |
| **Ember's defaults marked in the settings editor** | A setting whose default Ember changed (the editor font, the theme, the title bar and the rest) has a small Ember default tag beside its title in VS Code's settings editor. Your own value still wins. Source builds only. | So you can tell Ember's choices from VS Code's own defaults. | The settings editor says “Default value changed” and names the extension in a hover; a default patched into the editor shows nothing. |
| **The chat and Work side by side** | Ember's right side bar lays its views side by side instead of stacked: the chat, then Work. Drag the handle between them to size each, collapse either to a thin strip, or hide Work. Each keeps its width. Source builds only. | A list of chats reads best as a column beside the chat, not squeezed under it. | A side bar stacks its views top to bottom; only the bottom panel lays them side by side. |
| **No title row over the chat** | While Ember's chat is in the right side bar, the bar has no title row of its own: the chat's header row is its top. Maximize is in the chat's ⋯ menu. Source builds only. | The row said only "Ember" and took 35 pixels from the chat; Ember's buttons are in the title bar. | A side bar always shows a title row with its name or its views' icons. |
| **A notification that asks something stays up** | A notification with buttons (one that asks you something) stays on screen until you answer or close it, instead of disappearing into the bell after a few seconds. Ember's own notifications keep the usual timing: most point at a question that also waits in the chat, which Ember can't take down once you answer it there. Source builds only. | A question that hides itself while you're reading the chat is easy to miss, and whatever waited on it stays stuck. | Only an error with buttons stays up; any other notification hides after about 10 to 15 seconds. |
| **No question about fetching periodically** | The built-in Git never asks whether to run git fetch periodically. Periodic fetch stays off unless you turn on Git: Autofetch yourself. Source builds only. | The question came after a chat's first push, and turning it on would let a background fetch change what a careful force push checks against. | After the first push or pull in a folder, a notification asks whether to periodically run git fetch. |

Using Ember's extensions in stock VS Code or VSCodium instead? See [Ember in stock VS Code or VSCodium](ember-in-stock-vscode.md).
